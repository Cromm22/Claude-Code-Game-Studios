**Why module-private, not method-on-Service (round-15 R14-B4 design rationale).** The round-13 R12-B3 wording placed the registration accessors as methods on DisturbanceService's server-internal table, defended by H.39c's grep that they are NOT on `DisturbanceService.Client`. Round-14 surfaced (CD-elevated round-15 R14-B4) that the grep cannot catch the local-alias-to-Client-method injection pattern: `local accessor = DisturbanceService.RegisterPredatorLockChangedSignal; ... DisturbanceService.Client.SomeNewMethod = function(self, player, payload) accessor(DisturbanceService, payload) end`. The pattern is grep-undetectable because the violating Service.Client declaration is syntactically-distinct from the accessor's declaration and the alias resolves to a Service-internal function. Module-private accessors eliminate the threat surface mechanically — there is no Service or Service.Client method to alias-back-to; the accessor's only entry point is `require()`-chain access through the handshake module, which has no Knit Client surface and is reachable only from server-side code paths under `src/server/**`. F.1's "no MVP-internal hard dependencies" is preserved — neither service `Knit.GetService`s the other; both `require()` the handshake module.

**Why register-time subscribe, not KnitStart-side subscribe (round-15 R14-B2 design rationale).** The round-13 R12-B3 wording placed DisturbanceService's `:Connect` to `OnPredatorStateChanged` inside DisturbanceService:KnitStart's body, after a `RegisterPredatorStateChangedSignal` invocation completed. Round-14 surfaced (CD-elevated round-15 R14-B2) that this pattern admits a KnitStart inter-service ordering race: Knit guarantees all KnitInits complete before any KnitStart fires, but KnitStart ordering BETWEEN services is undefined per the Knit framework specification. If DisturbanceService:KnitStart runs before PredatorAI:KnitStart, the `RegisterPredatorStateChangedSignal` invocation has not yet happened — `self._onPredatorStateChangedBindable` is nil — and DisturbanceService:KnitStart's `:Connect(...)` would deterministic-nil-dereference. The register-time subscribe pattern moves the `:Connect` INSIDE `RegisterPredatorStateChangedSignal`'s body: regardless of KnitStart ordering, the `:Connect` happens at the moment Predator AI invokes the registration accessor — by which time DisturbanceService has either (a) already written its handler slot via `setOnPredatorStateChangedHandler` (handler is live; `:Connect` registers immediately) OR (b) not yet, in which case the registration accessor queues the `:Connect` until the slot-writer drains the queue. The deferral is implementation-internal to the handshake module; both KnitStart-orderings produce deterministic subscription. The pattern eliminates the round-9 KnitStart inter-service ordering risk class structurally.
