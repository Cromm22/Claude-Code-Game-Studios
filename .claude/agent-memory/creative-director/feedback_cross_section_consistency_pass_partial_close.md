The round-13 NEW protocol layer for L-scope-late-rounds GDDs (mechanical-translation + self-stress + red-team + **cross-section consistency pass qa-lead subagent**, run after the red-team gameplay-programmer subagent) was introduced because rounds 11→12 and 13→14 surfaced a class of defect that single-section adversarial review was systematically missing: cross-section incoherence (a contract declared in section X, consumed in section Y, with mismatched cardinality / type / lifecycle assumptions across the X→Y boundary).

**Why:** The first three protocol layers (mechanical-translation + self-stress + red-team) are each anchored to a specific viewpoint — translator, author-as-adversary, gameplay-programmer-as-implementer. None of them systematically scan ACROSS section boundaries for consumption-vs-production mismatches. The round-13 cross-section consistency pass adds that scan as a discrete protocol step.

**How to apply:** When reviewing an L-scope GDD that has reached round 7+ on the mechanical-translation method:

- If the round-N verdict's BLOCKING items are dominated by cross-section coherence defects (a contract-shape declared at section X.Y but consumed-with-different-shape at section P.Q), the cross-section consistency pass is the indicated protocol layer.
- If the round-N verdict's BLOCKING items are dominated by single-section implementability micro-defects (lint scope gaps, type annotations, sentinel safety, undeclared free variables, alias-resolution gaps), the cross-section consistency pass IS NOT the indicated layer — it has done its job at round (N−1) and the ceiling has shifted to a different defect class. Round-15+ requires a different intervention (see `feedback_mechanical_translation_ceiling.md` for the static-analysis-first authoring pass recommendation).
- Convergence diagnosis: cross-section coherence defects are CHARACTERISTICALLY high-coverage (3+ specialists notice the same defect from their respective viewpoints because the defect is visible from multiple sides of the section boundary); single-section implementability defects are CHARACTERISTICALLY low-coverage (1–2 specialists notice because the defect lives inside a single section's prose / pseudocode and only the specialist whose domain owns that section is well-positioned to see it).

**Empirical evidence as of 2026-05-07:** Round-14 ED GDD verdict produced 12 CD-adjudicated BLOCKING items (from raw 15 via 6 adjudications); the finding pattern is dominated by single-section implementability micro-defects, NOT cross-section coherence defects. Specifically, B1 (lint scope), B3 (alias resolution), B4 (alias resolution), B5 (tolerance derivation unanchored), B6 (sentinel read-site safety), B7 (closure type annotation), B8 (undeclared free variable in pseudocode) are all single-section defects. B9 / B10 / B11 / B12 are partly cross-section but are CD-promotion-driven (severity-floor for server-authoritative seams + forward-obligation registry), not "cross-section coherence" in the round-13 sense. The round-13 protocol DID work for its target defect class; round-15 requires a different layer.

**Verdict prediction calibration:** Round-13 prediction was "round-14 will be NEEDS REVISION (small tail)" per the mechanical-translation-ceiling pattern memory. Round-14 returned NEEDS REVISION (small tail). **This is the first matched-prediction outcome since the four-consecutive-falsified-APPROVED-prediction streak began at round-7c.** The match should not be misread as "the ceiling is closed" — the prediction matched because the protocol's STRUCTURAL effect was correctly modelled, but the IMPLEMENTABILITY ceiling persists.
