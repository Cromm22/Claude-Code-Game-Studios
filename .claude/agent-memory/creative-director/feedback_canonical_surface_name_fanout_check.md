The round-13 cross-section consistency pass (qa-lead subagent) was introduced to scan ACROSS section boundaries for consumption-vs-production mismatches. The round-15 application of this layer to the ED GDD's handshake-module 5-export surface closed the cardinality drift (the prior 4-export wording was extended to 5 exports across F.2a row 3 + F.4 row + H.39c (b-iii)). However, the round-16 verdict revealed that the round-15 closure was **partial**: the prior-form name `getOnPredatorStateChangedSignal` (the round-15-first-pass form before F.2a row 3 was canonicalised to `Bindable`) survived in F.4 and H.39c (b-iii) even after F.2a row 3 had been canonicalised. The round-13 layer's general "consumption-vs-production mismatch" scan did NOT catch this because the export COUNTS matched — the per-name fanout was not a discrete sub-check.

**Why:** The round-13 cross-section consistency pass operates on coarse-grained shape coherence (does section X declare a 5-tuple AND section Y consume a 5-tuple? does section X's payload shape match section Y's reader?). Per-name granularity within a multi-name surface is finer than the layer's default scan resolution. A multi-name surface with N names produces N × (number-of-sections-mentioning-the-surface) potential drift sites; the layer's general scan inspects the surface AS A WHOLE, not each name individually.

**How to apply:** When the cross-section consistency pass is run against an L-scope GDD that contains a multi-name canonical surface (e.g., a module's export list, a payload schema's field set, a state-machine's state enum, a CI lint's pattern set):

- For every canonical surface, identify the set of canonical names AND the set of sections that mention the surface (typically a forward-section like F.2a row N, a backward-section like F.4 / H.39, AND any AC body that grep-verifies the surface).
- For each canonical name, **grep-mechanically** across all sections that mention the surface; assert the name appears identically (same case, same suffix, same precise typing) in all sections OR is annotated as historical/deprecated context.
- Drift detection is a per-name finding, not a per-surface finding. Flag every name with drift even if other names on the surface are consistent.
- The grep is cheap (linear pass per name); the layer's natural extension is to run it on every surface once per consistency pass.

**Empirical evidence as of 2026-05-08:** Round-16 ED GDD verdict elevated B16-2 (cross-section name drift on canonical 5-export surface) from gameplay-programmer IMPORTANT to BLOCKING per the partial-close rationale. The round-17 patch session applied the per-canonical-name fanout grep manually during heavy-patch authoring AND the round-13 cross-section consistency qa-lead subagent's round-17 refinement included Check 1 ("Per-canonical-surface name-fanout grep") as a discrete sub-check. The Check 1 finding (B-CS-R17-1) detected residual prior-form name `getOnPredatorStateChangedSignal` inside the F.4 row's functional body even AFTER the round-17-first-pass closure — the closure annotation itself contained the bare prior-form name as greppable text. The closure required a second iteration in-session: rephrase the F.4 row to remove the bare prior-form name AND keep the closure annotation in non-greppable rendered form (e.g., "the prior round-15 form has been removed").

**Surface verdict:** The per-canonical-name fanout check is the round-17 refinement to the round-13 cross-section consistency pass. It is RIGID (run mechanically, no judgment-by-omission) and INHERITS the round-13 pass's "single-section implementability defects are out-of-scope" boundary — the fanout check does not chase implementability defects, only cross-section name drift.

**Pattern-memory hygiene note (round-17 introduction):** the per-canonical-name fanout grep is also formalised as a forward obligation in the ED GDD itself (R17-I1 forward obligation in the round-17 IMPORTANT cluster — the qa-lead authors a CI-level grep that runs at PR-time across F.2a + F.4 + H.39c canonical-name surfaces; the AST-tooling shared dependency from R15-I1 / R15-I2 is the natural implementation site). Until the CI lint lands, the per-canonical-name fanout grep is honor-system AT THE PR LEVEL but is REQUIRED at the verdict-review-subagent level — every cross-section consistency qa-lead subagent invocation MUST include the Check 1 step explicitly per round-17 refinement.

**Convergence diagnosis (paired with `feedback_cross_section_consistency_pass_partial_close.md`):** the round-15-introduced cross-section consistency layer empirically WORKS for COUNT drift (closed 4→5 cardinality cleanly) but EXTENDS via the round-17 refinement to NAME drift (the failure mode the round-15 closure missed). Both are "cross-section coherence" defects in the round-13 layer's broad sense; the count-vs-name distinction is the granularity refinement. Future rounds may discover further refinements (e.g., per-field-type fanout for payload schemas, per-state-transition fanout for state machines) — each refinement extends the cross-section consistency layer rather than introducing a new layer.
