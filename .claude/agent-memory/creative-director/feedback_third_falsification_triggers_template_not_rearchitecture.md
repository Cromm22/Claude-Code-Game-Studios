When adjudicating whether a recurring defect class trips the re-architecture / fifth-flag bar, distinguish a recurrence INSIDE a settled abstraction from a recurrence on a bolted-on LEAF feature.

**The discriminator (reusable):**
- **Re-architecture IS warranted** when a class reappears INSIDE the abstraction a prior fix claimed to dissolve (the fifth-flag pattern — the abstraction is leaking, so the abstraction must be rebuilt).
- **Re-architecture is NOT warranted** — it is the enumerable "next ring" — when the recurrence is on a feature that was never enclosed by any spine abstraction. You cannot fifth-flag an abstraction that was never built.

**The rule this memory adds (the round-25 PC ruling):** A bolted-on leaf feature can still earn an escalation short of re-architecture. When such a feature fails "gate-complete" a **third** consecutive time — i.e. each prior fix's OWN edits spawned the next miss (a non-convergence signal, not a one-off) — the re-architecture bar **TRIPS (affirmed) but DISCHARGES as a one-time feature-completeness-TEMPLATE authoring pass**, not a full feature re-architecture and not a patch-as-usual round. The template pass is itself the next falsification test: a **fourth** falsified gate-complete claim AFTER a disciplined template pass flips the discriminator (the feature has now proven it needs a consolidating abstraction) and earns a genuine re-architecture.

**Why a template, not another patch:** Per-round patching had been closing each leaf feature at the level it was critiqued, but a sibling completeness dimension (transport schema, render-routing discriminator, audibility floor, AC non-vacuity) kept being un-enumerated — so each fix shipped its own next miss. A standing completeness TEMPLATE forces every surface of the feature through the same checklist at once, which is what closes a non-converging tail. The template (round-25 PC, the world-response-cue + dead-emote cluster):

1. **Transport** — every signal has a declared payload schema with NAMED fields (closes "a prose rule that never reaches the transport contract": e.g. a dead-state discriminator field so the client can route render).
2. **Authority** — server-authoritative, non-forgeable.
3. **Gate-measures-the-guarantee** — the AC tests the ACTUAL property, not a true-but-insufficient proxy (e.g. "payload has no position field" is true but does NOT close a dead-position-tell when the client can resolve the lingering corpse position itself).
4. **Domain-correct config** — floors in-range, declared at a real site, registry-synced (no `>0` where the registered range floor is higher; no field a config-gate must read that has no declaration site).
5. **Non-vacuous concurrent test** — negatives are interleaved with a proven-live positive in ONE test body (a half-wired handler that fires on both the real trigger AND on noise can pass sequenced negatives).

**Why NOT MAJOR even though the bar tripped:** the spine was independently verified sound on every axis the leaf cluster doesn't touch (network authority PROTECT, build BUILDABLE, formulas degenerate-free, ai PASS, authored design honest), the recurrence was confined to ONE enumerable leaf cluster, and every miss was mechanical (a schema field, a config floor, a knob-range fix, AC rewrites). NEEDS REVISION + a prescribed template pass + reserved full panel is the proportionate escalation.

**Adjudication note (reusable):** a "the design is honest, the bar should not re-open" lens (e.g. game-designer) and a "third gate-complete miss found" lens (network/ux/qa/audio) are answering DISJOINT questions — the falsification test governs gate-COMPLETENESS (is the feature buildable/enforceable/testable end-to-end?), NOT design-completeness (is the authored intent sound?). A clean design lens does not save a round that failed the gate-completeness test.

**Surfaced by:** the round-25 Player Controller closure-gate panel (2026-06-15). The world-response-cue + dead-emote-billboard cluster failed gate-complete a third time (round-22 claim falsified by round-23; round-24 single-owner cue-completeness pass falsified by round-25), via a quadruple convergence (network ⊕ ux ⊕ qa ⊕ systems) on the `OnEmoteBroadcast` dead-state-discriminator gap + an audio onset-floor gap. **Round-26 refinement (2026-06-15) — two corrections that did NOT trip the bar early, plus an axis-routing rule.** A round-26 full panel run by USER OVERRIDE against the BYTE-UNCHANGED round-24 artifact (no template pass had executed) re-confirmed all ~9 round-25 BLOCKING and surfaced three things. RULING: the bar STAYS at one-time template pass. The fourth-falsification trigger requires "a fourth falsified claim AFTER a disciplined template pass" — neither **fourth** nor **AFTER** was met (no template pass ran; re-confirming round-25 ≠ a fourth falsification — you cannot fail a test never sat). Two findings SHARPEN the template's scope rather than refute it:
- **The class is WIDER than the original leaf cluster** — build-from-artifact found the SAME "canonical surface under-declares the contract" class in PC's *core* C.9 inbound-subscription table (preamble "two signals" vs body wiring ≥six: RunEnded, OnDisturbanceBandCrossed, OnEscapeBeaconActivated, OnBeaconWindowSurvived, OnPlayerOxygenExpired, +), reversing round-25's BUILDABLE. This does NOT widen the class out of template-scope — it CONFIRMS the diagnosis: the class is a documentation-completeness DISCIPLINE failure recurring at every canonical surface, not a structural defect localized to one feature. The cure is a discipline (template) applied uniformly; a consolidating abstraction only fits recurrence INSIDE one settled mechanism. The finding widens the template's APPLICATION SURFACE (add the inbound subscription table as a row to check), NOT the defect class. A wider application surface is a prescription refinement, never a re-architecture trigger.
- **The prescribed Transport fix was INSUFFICIENT** — network found that even WITH a dead-state discriminator field, an exploit-client ignoring client-side routing still renders the corpse billboard, because emote is server-accepted-and-broadcast while ping is server-rejected (asymmetric trust boundary). Template row-1 Transport alone does NOT close the cluster; suppression must be SERVER-DRIVEN (server suppresses the corpse-locating broadcast or routes through a non-locating channel) — i.e. it fails row-2 Authority. This TIGHTENS the T-1/T-2 scope ("suppression decided server-side from server-truth, never client-resolved"); it does not require an abstraction.

**Decisive logic:** the fourth-falsification trigger tests whether DISCIPLINE can close the cluster. When discipline has not yet been attempted, findings that "the discipline must cover more surfaces / assert server-authority harder" are evidence FOR the template path, not against it. Calling re-architecture on such findings would skip the falsification test the precedent exists to run. Round-26 prescription = the SAME template pass with WIDENED scope (+ inbound subscription table) and TIGHTENED T-1/T-2 (server-authoritative emote suppression; verified by a combined ux+network narrow gate against the exploit-client case). Full panel still reserved for round-27. NEVER predict APPROVED for the template round or round-27.

**Design-completeness vs gate-completeness axis routing (reusable, extends the round-25 adjudication note):** when game-designer surfaces fantasy-delivery holes on a closure-track round (round-26: sprint has no specified necessity → never-sprint dominant; death-cost unanchored to the RM economy → shared-fragility undesigned; emote coordination has no emitter→recipient feedback loop), these are a DIFFERENT axis from the round-23 gate-completeness test and do NOT gate the template round. They are design holes in the ORIGINAL mechanic, not "prose rule never reached its transport/config/gate contract" instances. Route them to a SEPARATE design-pass workstream owned by game-designer, sequenced AFTER the cluster is gate-closed — do NOT fold fantasy-delivery redesign into a single-owner mechanical template pass (it re-seeds the non-convergence the template exists to break). game-designer is correct that these "survived 25 rounds because the panel axis was always implementation" — and that is precisely why they cannot become the gating verdict of a closure-track round without re-opening the whole design.
